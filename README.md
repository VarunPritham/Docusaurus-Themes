# Confluence Docs Bricks

A Docusaurus site preconfigured as a **Confluence replacement target**: small,
composable React components ("bricks") that mirror the most-used Confluence
elements, so an LLM (or a human) can convert any Confluence page into an MDX
file with nothing lost.

Built for restricted networks: **zero dependencies beyond Docusaurus + React,
zero external URLs, zero runtime network calls.** Install from a private npm
mirror and it works fully offline.

## Quick start

```bash
npm install
npm start        # dev server on :3000
npm run build    # static production build → build/
```

## The bricks

All in `src/components/Bricks/` — one import line in any MDX file:

```mdx
import { Badge, Panel, Expand, PropertiesTable, TaskList,
         Figure, Attachments, Ticket, Mention, Columns, Column, Meta }
  from '@site/src/components/Bricks';
```

| Confluence element | Brick |
|---|---|
| Status lozenge | `<Badge color="green">DONE</Badge>` |
| Info/Note/Warning/Success/Error panel | `<Panel type="warning">…</Panel>` |
| Expand macro | `<Expand title="…">…</Expand>` |
| Page properties | `<PropertiesTable rows={[{name, value}]} />` |
| Action items | `<TaskList items={[{task, owner, due, done}]} />` |
| Image / draw.io diagram | `<Figure src="/img/x.png" caption="…" />` |
| Attachments | `<Attachments files={[{name, url, size}]} />` |
| Jira issue | `<Ticket id="DATA-1042" status="In Progress" />` |
| @mention | `<Mention name="Priya Shah" />` |
| Column layout | `<Columns><Column>…</Column></Columns>` |
| Page byline | `<Meta owner="…" lastUpdated="…" status="…" />` |
| Children display | `<DocCardList />` (built into Docusaurus) |
| TOC, headings, tables, code, lists | plain markdown — automatic |

**Live examples of every brick:** `docs/bricks-reference.mdx` — this page is
the canonical pattern reference for authoring converted pages.

## Page hierarchy

The sidebar is autogenerated from folders. Confluence hierarchy maps 1:1:

```
Confluence: Data Platform > LakeBridge > Setup Guide
Here:       docs/data-platform/lakebridge/setup-guide.mdx
```

- Parent pages: `index.mdx` inside the folder (use `<DocCardList />` to list children)
- Folder label/order: `_category_.json`
- Never edit `sidebars.ts` when adding pages

A working sample hierarchy lives in `docs/data-platform/` — delete it when
real content arrives.

## Conversion contract (for the LLM pipeline)

Given a Confluence page from the API:

1. `ancestors` → folder path under `docs/`
2. Title, author, last-modified → frontmatter `title` + `<Meta />` byline
3. Body elements → markdown, plus the matching brick per the table above
4. Attachments → files into `static/files/` (images into `static/img/`), listed with `<Attachments />`
5. draw.io diagrams → exported PNG into `static/img/`, embedded with `<Figure />`

## Security posture

- No CDN links, no web fonts, no analytics, no iframes
- All assets served from `static/` and `build/assets/`
- Verify any time with:
  ```bash
  grep -rEoh "https?://[^\"' )]+" src/ docs/ docusaurus.config.ts | sort -u
  ```
  Expected output: only `localhost`, XML namespaces, and `*.internal` sample links.
